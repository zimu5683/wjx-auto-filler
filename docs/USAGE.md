# 使用说明（问卷自动填表 / wjx-auto-filler）

适用版本：**1.0.x**　|　适用系统：**Android 7.0（API 24）及以上**
（本文按钮名与 App 内文案一致；若后续界面调整，以 App 内实际显示为准。）

---

## 0. 一分钟上手

1. 打开 App → 顶部输入问卷链接，或点 **扫码** / **相册** 识别二维码
2. 点 **解析问卷** → 弹出「题目清单」
3. 在 **字段映射** 表里逐行填 **目标字段**（题号 / 题干关键词）与 **填充内容**
4. 需要多份答案就点 **新增组**（方案 1 / 方案 2 …），每组单独配置
5. 点 **并行提交** → 在 **提交结果** 区查看每组结果
6. 若提示需要人机验证：点 **人工验证后重试**，由你本人完成一次验证，App 会继续用纯接口提交（见 7.1）
7. 有新版本时点 **检查更新** 下载安装

---

## 1. 安装与首次启动

1. 从 [Releases](https://github.com/zimu5683/wjx-auto-filler/releases) 下载
   `wjx-autofill-<版本>-universal.apk`
2. 系统提示「未知来源」时，进入 **设置 → 应用 → 特殊权限 → 安装未知应用**，允许对应来源
   （该 APK 是**通用包**，内含 arm64-v8a / armeabi-v7a / x86 / x86_64 四个 ABI，任意 Android 7.0+ 设备直接安装）
3. 首次打开无需登录、无需注册

**权限说明**

| 权限 | 用途 | 拒绝后影响 |
| --- | --- | --- |
| 相机 `CAMERA` | **扫码** 实时识别问卷二维码 | 仍可用 **相册** 或直接粘贴链接 |
| 读取所选图片（系统照片选择器） | **相册** 导入二维码截图 | 仍可用扫码或粘贴链接 |
| 网络 `INTERNET` | 解析问卷、并行提交、检查更新 | 无法解析与提交 |
| 安装 APK（`REQUEST_INSTALL_PACKAGES`） | 应用内更新时唤起系统安装器 | 可手动到 Release 下载安装 |
| 通知（`POST_NOTIFICATIONS`，Android 13+） | **定时自动提交**的常驻通知、开放提醒与结果通知 | 到点不会提醒、常驻通知不可见（界面会提示） |
| 前台服务 + 唤醒锁（`FOREGROUND_SERVICE` / `..._SPECIAL_USE` / `WAKE_LOCK`） | 让定时任务常驻并在到点可靠执行 | 定时功能不可用；填表/提交等其他功能不受影响 |
| 振动 / 全屏提醒（`VIBRATE` / `USE_FULL_SCREEN_INTENT`） | 开放提醒与「需要人机验证」通知的醒目提醒 | 仅提示强度降低 |

App **不申请**存储写入、通讯录、定位、电话等权限；模板文件通过系统文件选择器（SAF）读写，无需存储权限。
验证码兜底使用**系统自带 WebView**，不新增额外权限。通知与前台服务权限**只有定时功能使用**，不开启定时任务时不会申请与常驻。

## 2. 导入问卷

三种方式任选其一，链接会填入顶部「问卷链接」输入框：

1. **扫码**：进入「扫码识别问卷链接」页，把二维码放入取景框；识别成功后自动返回并回填链接。
   页面提供 **手电筒：开/关**；无可用后置相机时会提示改用相册。
2. **相册**：从系统照片选择器选二维码截图，本地解码后回填链接（图片不写入、不上传）。
3. **粘贴链接**：直接把链接粘进输入框。支持形式：
   - `https://www.wjx.cn/vm/Q0DQewW.aspx`
   - `https://v.wjx.cn/vm/P2M09FG.aspx`（**`*.wjx.cn` 子域短链**，如 `www.` / `v.`）
   - `https://www.wjx.cn/vm/Q0DQewW.aspx#`（带锚点）
   - `http://` 会被规范化为 `https://`

链接必须是 **https + `wjx.cn` 域（含任意子域）+ 带问卷 ID**，否则提示
「链接无效：请填写 https://<子域>.wjx.cn/vm/xxxx.aspx 形式的问卷链接」。

## 3. 解析问卷

点 **解析问卷** → 拉取问卷页面，弹出 **题目清单**：

- 显示问卷标题与题目总数（「已解析：<标题>（共 N 题）」）
- 点选任一题目，会把该题的**标识**（题号，如 `1` / `q1`）自动填进字段映射表的**左栏**
- 点 **关闭** 收起题目清单

解析失败时：

| 提示 | 原因 | 处理 |
| --- | --- | --- |
| 网络连接失败，请检查网络后重试 | 无网络 / DNS / 超时 | 检查网络后重试 |
| 问卷服务器返回异常（HTTP xxx） | 服务端异常或链接失效 | 稍后重试 / 确认链接 |
| 问卷页面解析失败，可能是问卷已关闭或页面改版 | 无 `jqnonce` / 无题目 / 非 HTML | 确认问卷仍开放；持续出现请提 issue |
| 该问卷为分页/逐题模式，暂不支持自动填写 | 问卷是「一页一题」模式 | 本版本不支持（避免只提交半份答卷），请用官方页面填写 |

> 解析只读取公开问卷页面，不提交任何数据。

## 4. 字段映射（左右双栏）

「字段映射」是一张两列表格：

| 左栏：目标字段（题号 / 题干关键词） | 右栏：填充内容 |
| --- | --- |
| `1` 或 `q1` 或 `姓名` | 你要填的答案 |

**左栏匹配规则**（按顺序尝试，首个命中即停止）：

1. **精确题号**：`1`、`q1` 这类纯数字/题号 → 直接命中该题
2. **题干包含**：如 `姓名` → 命中题干里含该关键词的题（中文按原文子串，英文忽略大小写）
3. **选项文本**：左栏写选项文字（如 `男`）→ 命中含该选项的题，右栏留空即取该选项

**右栏填值规则**：

| 题型 | 填法 |
| --- | --- |
| 填空 | 直接写文本（上限 3000 字） |
| 单选 / 下拉 | 写选项文字或选项值 |
| 多选 | 多个选项用 `\|` 分隔，例如 `A\|C` |
| 矩阵 / 滑块 | **暂不支持**，会明确报错而不是静默跳过 |

**操作按钮**：**新增一行** / **删除本行** / **删除选中**（先勾选，未勾选会提示）/ **清空全部**（二次确认）。

**匹配结果分两类（v1.0.5 起支持「超量预填」）**：

- **可跳过**：左栏字段在这份问卷里**找不到对应题目** → 该字段被**跳过**，**不影响本次提交**；
  结果区会显式列出：「已跳过 N 个未匹配字段：<字段列表>（问卷里没有这些字段，不影响本次提交）」
- **仍会失败（整次提交中止，不会提交半份答卷）**：
  - 一个关键词命中多道题（歧义）→ 提示改用题号
  - 多个字段指向同一题（冲突）
  - 取值不在选项中（单选 / 下拉 / 多选解析失败）
  - **全部字段都被跳过**（没有任何可提交的题目）

> **超量预填的意义**：**一份字段表可以适配多份问卷** —— 把可能用到的字段都写上，
> 问卷里没有的会被自动跳过并如实列出，而不是让整批提交失败。
> 空行（左栏留空）与「右栏不填」的条目会被直接忽略：不算跳过、也不会失败。

> 提示：先用 **解析问卷** 打开题目清单、点选题目自动填左栏，比手写标识更稳。

## 5. 内容组（多份答案）

- **新增组**：默认命名「方案 1 / 方案 2 …」，每组有**独立的字段映射**
- **重命名**：自定义组名（如「方案 A」）
- **删除组**：删除该组及其全部映射（二次确认）；**至少保留一个内容组**
- 顶部切换组标签即可编辑不同组

**并发**：提交时各组**并行**执行，默认并发 2，可在 1–5 之间调整（越界自动收敛）。
每组使用**独立会话**（各自重新获取页面令牌与 Cookie），互不串号。
建议并发不超过 3 并适当间隔，避免触发平台频率风控。

## 6. 模板：保存 / 载入 / 删除

- **保存模板**：填写模板名称后保存当前配置（问卷链接 + 各组字段映射），存到应用内部存储；成功后提示「模板已保存」
- **载入模板**：从模板列表选一个载入到当前编辑区
- **删除模板**：在模板列表里删除（二次确认「确定删除模板「<名称>」？此操作不可撤销。」），成功后提示「已删除模板「<名称>」」
- 没有模板时提示「还没有保存过模板」；保存失败提示「保存失败：无法写入本地配置」

> **v1.0.5 变更**：按用户要求**移除了「导入模板 / 导出模板」**（含粘贴 JSON 与文件选择）。
> 模板只保存在本机应用私有目录，**不支持导出备份** —— 卸载或换签名重装会丢失，请留意。
> 存储实现与文件格式仍见 [docs/API-CONTRACT.md](API-CONTRACT.md)；
> 配置损坏时 App 会自动**备份原文件**（`templates.json.bad-<时间戳>`）并以空配置启动，不会静默丢数据。

## 7. 并行提交与查看结果

1. 确认问卷链接已填、每组至少有一条字段映射（否则提示「请先填写或扫码获取问卷链接」/
   「请先配置至少一个字段映射」）
2. 点 **并行提交**：显示「正在并行提交 N 组…」，每组独立会话按问卷星表单协议提交
3. **提交结果** 区按组显示 **等待中 / 成功 / 失败**，并汇总「成功 N / 失败 M」
4. 失败的组可用 **重试失败组** 再跑一次（本工具**不会自动重试**，避免重复答卷）

> 铁律：HTTP 200 不等于提交成功。App 会按问卷星返回体判定（业务码 `10`/`11` 才算成功），
> 且只发**最小请求**：`ktimes = max(4, 页面值)`（下限 4 为实测有效值），未取得验证令牌时绝不携带
> `rn` / `captchaVerifyParam` / `sceneId`（实测补发这些字段会把成功响应变成 `7〒需要安全校验`）。
> App **不做本地门控**：无论页面开关为何值都先发一次真实提交，只有服务端返回 `7`/`22` 才进入人工验证兜底。

**错误对照表**（界面提示 → 含义 → 处理）

| 提示 | 含义 | 处理 |
| --- | --- | --- |
| 链接无效：… | 链接格式/域名不对 | 用 `https://<子域>.wjx.cn/vm/xxxx.aspx`（如 `www.wjx.cn`、`v.wjx.cn`） |
| 网络连接失败，请检查网络后重试 | 请求未完成 | 检查网络后重试 |
| 已跳过 N 个未匹配字段：…（问卷里没有这些字段，不影响本次提交） | 左栏有字段在这份问卷里**没有对应题目**（超量预填的正常情况） | 无需处理：该字段不提交，其余字段正常提交 |
| 字段未匹配：…（歧义 / 冲突 / 取值不在选项） | 匹配规则判定为**失败** | 按提示改用题号，或修正右栏取值 |
| 没有可提交的答案 | 该组过滤空值后无内容 | 补内容 |
| 答案超过 3000 字上限（题号 N） | 文本过长 | 缩短内容 |
| 题号 N（类型）暂不支持自动填写 | 矩阵/滑块等题型 | 该题请人工在官方页面填写 |
| 问卷服务端拒绝：<服务端文案> | 服务端业务校验失败（如「请输入正确的学号」） | 按文案修正内容 |
| 该问卷要求人机验证，纯接口无法提交 | 本次提交被**服务端**判需要安全校验：响应业务码 `7`/`22`（`22` 亦见于 `ktimes=0` 等请求形态异常；`useAliVerify=1` 的问卷通常返回 `7`）。App 不做本地门控，总是先发一次提交 | **不是终态**：点 **人工验证后重试** 由你本人完成一次验证（见 7.1）；该组机会用完后改用官方页面 |
| 该问卷为分页/逐题模式，暂不支持自动填写 | 分页问卷 | 用官方页面填写 |

> 本工具**不会**尝试绕过验证码或风控：人机验证由**你本人**完成，答案提交始终由 App 的纯 HTTP 引擎执行。

### 7.1 服务端返回业务码 7/22 时：人工验证后重试

**适用条件**：本次提交被服务端以业务码 `7`/`22` 拒绝（`useAliVerify=1` 的问卷通常如此；
`useAliVerify=0` 的问卷在正确请求形态下可直接纯接口提交成功，无需这一步）。App 不做本地门控，
总是先发一次真实提交，再按响应决定是否给出兜底入口。

收到 `E_CAPTCHA` 后 App **会自动进入验证界面**（不再要求你先点按钮）：

1. App 自动打开「人机验证」页面（也可随时点 **人工验证后重试** 重新进入）——
   WebView 加载**真实问卷 URL**，与提交引擎共享同一会话 Cookie。
   页面说明：「这是问卷平台要求的人机验证，App 不会替你绕过，也不会代你提交：请在下方网页里手动完成一次验证，
   完成后会自动返回并由 App 用接口继续提交这一组。」状态依次为：正在加载问卷页面… → 请在下方完成验证… → 验证完成
2. 在页面上**你本人完成一次阿里云验证**（滑块 / 点选）
3. App 收割验证令牌 `captchaVerifyParam` 并读回会话 Cookie，关闭验证页面；随后提示「正在用验证凭证重试该组…」
4. App 用该会话**重新拉取问卷页面**（取新的 `jqnonce` / `starttime`），再由**纯 HTTP 接口**提交，
   POST 体携带令牌与 `sceneId`；成功后服务端返回业务码 `10`，并提示「验证通过，该组已提交成功」
5. 令牌**单次有效且短命**：收割后须在 **60 秒内**完成提交，超时会提示「验证已过期，请重新验证」

**边界（重要）**：内置验证页面**只**用于唤起验证码控件与读取令牌 —— **不填表、不点提交、不接收任何答案数据**；
答案的构造与提交始终由 App 的 HTTP 引擎完成。

**兜底机会（每个组独立）**：**每个需要兜底的组各有 1 次机会，不设跨组上限**。
多组都需要验证时**逐组处理** —— 自动进入与按钮都针对其中**第一个**尚未兜底的组；该组处理完后指向下一组，全部处理完按钮隐藏。

自动进入只针对「还没用过机会」的组；**若你进入后直接返回（没有真正发起验证），该组不会再次自动弹出**，
避免「返回 → 自动进入」死循环 —— 此时可用 **人工验证后重试** 手动重试。
App **不自动点击、不自动解题**：验证必须由你本人完成。

**是否消耗该组机会**（只有验证环节**真正启动过**才消耗）：

| 情形 | 消耗机会 | 说明 |
| --- | --- | --- |
| 用户主动取消（返回 / 关闭验证页面） | **不消耗** | 按钮保留，可再点 |
| 已唤起验证码但超时未取得令牌 | 消耗 | 该组不再显示按钮 |
| 取得令牌但提交仍失败 / 令牌过期 | 消耗 | 该组不再显示按钮 |
| 页面无验证入口、设备无 WebView（结构性失败） | 不消耗，但**立即终态** | 按钮对**全部未兜底组**隐藏 |

**降级提示（以下均为 App 内实际文案）**

| 提示 | 原因 | 按钮 |
| --- | --- | --- |
| 已取消人工验证 | 你返回/取消了验证页面 | 保留（**不消耗**机会，可再点） |
| 未检测到验证结果，请重试 | 已唤起验证码但 180 秒内未收割到令牌，或令牌为空 | **消耗**该组机会 |
| 验证已过期，请重新验证 | 收割后超过 60 秒才提交，或服务端再次返回码 7/22 | **消耗**该组机会 |
| 设备无法打开验证页面，请在浏览器中手工填写该问卷 | 设备无可用 WebView 内核 | 不消耗，但按钮对全部未兜底组**立即隐藏**（终态） |
| 验证页面结构已变化，无法自动唤起验证码 | 问卷星页面改版（页面无 `loadCaptchShow`） | 同上 |
| 无法唤起验证码：<原因> | 唤起脚本执行异常 | 同上 |
| 该组已尝试过人工验证，仍未成功 | 该组机会已消耗，再点无意义 | 该组不再显示按钮 |

> 验证后仍失败时，结果区显示「验证后仍然失败：<原因>」；成功则显示「验证通过，该组已提交成功」。

## 8. 定时自动提交（前台常驻）

适合「问卷在某个时间点才开放」的场景：提前配好，到点由 App 自动提交并推送结果。

### 8.1 操作步骤

1. **解析问卷**：顶部状态条显示开放状态 —— 「开放时间未知：点「解析问卷」获取」/「尚未开放，将于 2026-09-23 09:00 开放」/「已开放，可提交」。
   开放时间优先取页面时间戳 `qBeginDate`，其次读「此问卷将于 … 开放」文案；解析不出来按「未知」处理，**不会拦截手动提交**。
   未开放时手动提交按钮变为 **尚未开放 · 立即提交**，点击会二次确认「当前时间早于开放时间 …，现在提交很可能被服务端拒绝。仍要手动提交吗？」
2. **保存模板**：定时任务必须绑定一份模板；未保存会提示「请先「保存模板」，定时任务需要绑定一份模板」。
3. **填写定时参数**：
   - **问卷开放时间**：格式 `2026-09-23 09:00`（未填会提示「请先填写问卷开放时间（格式 2026-09-23 09:00）」）
   - **提前提醒（分钟）**：默认 **10**；`0` = 不提前提醒；超出 0–1440 会自动收敛
   - **到点响铃提醒（默认开）** / **到点震动提醒（默认开）**：可分别关闭；两者都关时仍会推送
     **高优先级全屏通知**（系统不允许全屏时退化为高优先级通知，点击进入）
4. **打开「到点自动提交」开关**：提示「定时提交已开启，到点会自动提交并通知」，并出现常驻通知「定时提交已开启 / 等待问卷开放…」。
   顶部状态行显示「定时：<状态>　开放 <时间>」，状态取值：**已排定 / 已提醒 / 提交中 / 已完成 / 未成功 / 已取消**。
5. **到点**：自动提交并推送「定时提交结果」；关闭开关即取消（「定时任务已取消」）。

### 8.2 通知

| 通知 | 内容 |
| --- | --- |
| 常驻 | 定时提交已开启 / 等待问卷开放… |
| 开放提醒（提前 N 分钟） | 问卷即将开放 / `<模板名>` 将于 `<时间>` 开放，请留意人机验证 |
| 提交结果 | 定时提交结果 / 成功 N、失败 M 等摘要 |
| 需验证（全屏） | 定时提交需要人机验证 / 到点提交被人机验证拦截：… 尝试**全屏拉起验证页**；系统不允许全屏时退化为高优先级通知，点击进入（App 不会绕过验证码） |

通知渠道：**定时任务常驻 / 开放提醒 / 提交结果**。未授予通知权限时会提示「未授予通知权限：到点不会提醒，前台服务通知也不可见」。

### 8.3 约束与边界（如实）

- **同一时刻只允许 1 个定时任务**；再次保存会覆盖前一个
- 采用**前台常驻服务**（`specialUse` + 常驻通知），刻意**不用** AlarmManager/WorkManager
  （Android 15 对 dataSync 有 6 小时上限，跨夜定时会被掐断）
- **国产 ROM 仍可能杀掉进程**：建议**保持 App 在最近任务中**并**关闭电池优化**
- **不做设备重启后自动恢复**：重启后需要重新打开开关
- 前台服务启动失败会**降级为普通后台任务**（仅 App 在前台时有效），界面会显示失败原因
- 上次定时提交被系统中止时：「上次定时提交被系统中止，未确认是否已提交。为避免重复答卷，不会自动重跑，请手动确认。」

## 9. 人机验证检测

- **配置页不再显示「该问卷涉及人机验证」横幅**（v1.0.5 按用户要求移除）；**检测能力保留**：
  提交返回业务码 `7`/`22` 后 **App 会自动进入验证界面**（见 7.1），不自动点击、不自动解题
- **提前提醒（默认 10 分钟）**：开放前推送「问卷即将开放」，提醒你留意人机验证
- 到点被拦截时：推送高优先级通知并**尝试全屏拉起验证页**；回到 App 后收到 `E_CAPTCHA` 会**自动进入验证界面**
- **不做自主人机验证**：不自动点击、不自动解题 —— 验证由**你本人**完成一次；
  取消/返回后该组不会反复自动弹出，可用 **人工验证后重试** 手动重试
- **权威信号是提交响应码（7/22）**：页面开关只是快速提示；未检测到 ≠ 服务端一定放行

## 10. 检查更新

- 点 **检查更新**：匿名请求 GitHub Releases API 获取最新版本
  - 已最新：提示「已是最新版本 x.y.z」
  - 有新版：弹窗「发现新版本 x.y.z」+ 更新说明，可选 **下载并安装** / **以后再说** / **打开 Release 页面**
- 下载中显示进度百分比；下载完成后交系统安装器
- 若系统未允许安装未知应用，会提示先授权，返回后重新点击更新
- 该版本没有 APK 资产时会提示「该版本没有可下载的安装包，已打开 Release 页面」
- 检查失败提示「检查更新失败，请稍后再试」，不影响填表功能

安装时若提示「应用未安装 / 签名不一致」，说明当前安装包与 Release 包签名不同：
卸载后重装即可（**本地配置与模板会丢失**；v1.0.5 起已不支持导出模板，卸载前请留意）。

## 11. 常见问题

**Q：扫码没反应？**
A：光线不足或二维码太小/模糊。可截图后用 **相册** 导入，或直接粘贴链接。

**Q：解析出来题目不全 / 点选题目没反应？**
A：问卷星页面结构可能已调整。请提交 issue，附问卷链接（公开问卷）与实际表现。

**Q：提交提示「未匹配字段」？**
A：左栏标识与问卷题目对不上。打开 **解析问卷** 的题目清单，点选题目自动填入标识；
一个关键词命中多题时改用题号。

**Q：提交总是失败？**
A：先看结果区的平台返回信息。网络错误重试即可；若提示需要人机验证（业务码 7 或 22），
点 **人工验证后重试** 由你本人完成一次验证（见 7.1）—— `useAliVerify=1` 的问卷通常会遇到这一步，
而 `useAliVerify=0` 的问卷通常能直接提交成功；若该组机会已用完仍失败，请改用浏览器手工填写。

**Q：定时到点没有提交 / 没有提醒？**
A：依次检查：① App 是否还在**最近任务**中（国产 ROM 可能杀进程）；② 是否**关闭了电池优化**；
③ 是否授予**通知权限**（未授予会提示「到点不会提醒，前台服务通知也不可见」）；
④ 前台服务是否启动失败（界面会显示「已降级为普通后台任务，仅 App 在前台时有效」）。
另外本版**不做设备重启后自动恢复**，重启后需重新打开开关；若上次被系统中止，为避免重复答卷**不会自动重跑**。

**Q：能用于别人的问卷吗？**
A：仅限已获得问卷所有者许可的场景。未经授权的批量提交可能违反平台条款与法律。

## 12. 数据与隐私

- 所有配置与模板都保存在设备本地（应用私有目录 `filesDir/templates.json`），App 不上传、不备份到任何服务器
- 系统备份已关闭（`allowBackup=false`），配置不会被云备份带走
- 唯一的外发请求是：问卷星页面/提交接口（你主动触发）与 GitHub 更新检查
- 验证码兜底页面（WebView）只加载 `wjx.cn` 页面；为让验证令牌与提交会话配对，
  验证页面与提交引擎**共享同一会话 Cookie**，验证结束后立即清理该会话 Cookie；
  WebView 禁用本地文件访问与多窗口、禁止明文流量、只放行 `wjx.cn` 的 https 跳转、不注册任何 JS Bridge
- 卸载 App 即清除全部本地数据
